# DevOps Trainer

Локальный тренажёр для повторения учебных заметок по DevOps. 193 карточки в 14 разделах.
Никаких зависимостей, npm, сборки и бэкенда: HTML + CSS + JS плюс один JSON-файл.

## Запуск

Нужен браузер и Python 3 (для локального сервера). Открывать `index.html` двойным
щелчком нельзя: браузер блокирует `fetch` к `data/cards.json` из `file://`.

```powershell
.\start.ps1
```

Скрипт поднимает сервер и открывает <http://127.0.0.1:8000/>. Вручную:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Если порт 8000 занят, `start.ps1` не подбирает другой порт: он пишет, что порт занят,
и показывает, как найти и остановить процесс.

## Установка на телефон (PWA)

1. Откройте адрес приложения в браузере телефона.
2. Android/Chrome: меню браузера → «Установить приложение» (или «Добавить на главный экран»).
   iOS/Safari: «Поделиться» → «На экран «Домой»».
3. После первой успешной загрузки приложение работает без интернета — внизу появляется
   «Готово к работе без интернета». Пока эта надпись не появилась, офлайн-копия ещё не готова.
4. Когда выйдет новая версия, появится плашка «Доступна новая версия». Обновиться можно
   в любой момент, лучше после занятия: нажмите «Обновить». Прогресс, расписание и отметки
   «На разбор» при обновлении не стираются.

Приложение не отправляет наружу ответы, комментарии, прогресс и расписание: всё лежит
в `localStorage` устройства. Хостинг видит только запросы на загрузку файлов приложения
и может вести журналы — но не учебные данные.

## Перенос прогресса на телефон

1. На компьютере: «Данные» → «Резервная копия» — скачается JSON-файл.
2. Передайте файл на телефон любым способом: кабель, облако, мессенджер.
3. На телефоне: откройте приложение → «Данные» → «Восстановить копию» → выберите файл.
4. Автоматической синхронизации между устройствами нет: они не обмениваются данными сами.
5. Сохраняйте копию периодически. Локальное браузерное хранилище — не бессрочная гарантия:
   его можно очистить вместе с данными сайта или потерять при переустановке браузера.

## «На разбор»

Личные отметки карточек: кнопка «На разбор» на карточке в обоих режимах — до ответа,
после ответа и после раскрытия объяснения. Список открывается из меню («На разбор — N»),
в нём видно раздел, вопрос и комментарий, можно открыть карточку, изменить комментарий
или убрать отметку.

Отметки хранятся отдельно (`trainer.discussion.v1`), не считаются учебной попыткой и не
влияют на `training`, `reviews`, `progress`, `learning` и на `needs_review`. Если карточку
удалить из базы, запись останется с сохранённым снимком и предупреждением.

Экспорт для разбора: «Скопировать для разбора» (буфер обмена, при недоступности — текст
для ручного копирования) и «Скачать файл для разбора» — Markdown в UTF-8. Экспорт не
очищает список.

## Стабильный адрес и где живёт прогресс

Адрес всегда один: **<http://127.0.0.1:8000/>**. `localStorage` привязан к origin,
поэтому `:8000` и `:8123`, а также `localhost` и `127.0.0.1` — разные хранилища.
Переносите данные между ними только через резервную копию.

## Два режима занятия и два способа ответа

Режим занятия решает, **что происходит с расписанием**. Способ ответа решает, **как вы отвечаете**.

| | «Учить» | «Повторять» |
|---|---|---|
| Какие карточки | любые доступные, раздел выбираете сами | только те, у которых срок повторения наступил |
| Очередь | бесконечные круги | конечная очередь на сегодня |
| Способ ответа | «Тест с вариантами» или «Вспомнить самостоятельно» | всегда вспоминание, варианты — подсказка |
| Расписание | не меняется | меняется (единственный режим, который его двигает) |
| Что пишется в статистику | слой «Тренировка» | слой «Повторения» |
| Конец | кнопка «Закончить тренировку» | экран «На сегодня всё» |

### «Учить»

- Свободный выбор раздела: кнопка «Учить» в строке раздела, а также «Новые» (карточки
  без записи в расписании) и «Отработать ошибки».
- Бесконечные круги: круг заканчивается — начинается новый, карточки внутри круга не
  повторяются. Если в наборе больше одной карточки, первая карточка нового круга не совпадает
  с последней карточкой предыдущего.
- Доступны оба способа ответа, подсказки и объяснения.
- Для карточек, которые уже в расписании, тренировка **не меняет** `dueAt`, `intervalDays`,
  лестницу успешных повторений, `lastResult` и `lastReviewedAt`.
- Новая карточка после первой завершённой попытки получает запись в расписании: первое
  повторение — начало следующего локального календарного дня. Дальнейшие попытки в тот же
  день эту дату не сдвигают.
- Простое открытие карточки или раскрытие ответа без итоговой оценки ничего не записывает.
- «Отработать ошибки» — тоже тренировка: расписание она не меняет, даже если карточка
  уже просрочена.

### «Повторять»

- В очередь попадают только карточки с наступившим сроком (`dueAt` <= сейчас) и без
  пометки `needs_review`, если её не включили.
- Сначала самостоятельное вспоминание; «Показать варианты — подсказка» выдаёт варианты,
  «Показать ответ — самопроверка» показывает ответ и объяснение.
- Одна итоговая оценка на карточку за повторение: после оценки карточка уходит из очереди
  на будущее, повторно ответить в этой же сессии нельзя.
- В конце — экран «На сегодня всё» со счётчиками и переходом в «Учить» или к отработке ошибок.
- Повторная отработка ошибок идёт в режиме «Учить» и второй раз расписание не двигает.

## Расписание повторений

Ключ `trainer.learning.v1`, независимый от статистики. Для карточки хранится
`lastReviewedAt`, `dueAt`, `intervalDays`, `lastResult` и `independentSuccesses`.

Правила первой версии — **простые настройки, а не научно оптимальный алгоритм**:

- `failed` — повторение на следующий день, лестница интервалов сбрасывается;
- `hinted` — тоже на следующий день (так считается верный ответ с вариантами или с подсказкой);
- `independent` — интервал растёт по лестнице 3 → 7 → 14 → 30 дней;
- рост интервала возможен только при повторении в другой календарный день;
- `lastResult = "learned"` — карточка добавлена обучением: настоящего повторения ещё не было,
  `lastReviewedAt = null`.

Повторные попытки в один день:

| Сегодня | Что с `dueAt` |
|---|---|
| Успех, затем ещё успех | не меняется |
| Успех, затем ошибка или подсказка | завтра, интервал 0 |
| Ошибка/подсказка, затем успех | остаётся «завтра» |
| Ошибка, затем ещё ошибка | остаётся «завтра» |

Даты считаются по локальным календарным дням: «завтра» — это начало следующего дня по
часам браузера, а не «плюс 24 часа».

## Статистика: три слоя

| Слой | Ключ | Что означает |
|---|---|---|
| Тренировка | `trainer.training.v1` | ответы в режиме «Учить» |
| Повторения | `trainer.reviews.v1` | итоги запланированных повторений |
| Старая история | `trainer.progress.v1` | общая история до разделения режимов, только читается |

Семантика тренировки: `attempts = correct + wrong`, `correct = hinted + independent`.
Верный ответ в тесте с вариантами относится к `hinted`; в интерфейсе эта категория
называется «С вариантами». Самооценка «Не вспомнил» относится к `wrong`.
Для повторений: `attempts = independent + hinted + failed`.

Слои не смешиваются: успех в тренировке не улучшает результаты повторений, и наоборот.
Старая общая история показывается отдельным блоком и в новые слои не пересчитывается —
раньше события тренировок и повторений в ней не различались.

Экран «Статистика» показывает три блока и таблицу по разделам.

## Ошибки

«Отработать ошибки» собирает карточки из трёх источников: `training.wrong > 0`,
`reviews.failed > 0`, `progress.wrong > 0`. Объединение по `id`, без дублей.

Список исторический: успешный ответ не убирает карточку автоматически. Убрать её можно
только кнопкой «Очистить список ошибок», и она очищает **только список**: статистика,
расписание и старая история остаются. Для этого есть отдельный слой
`trainer.errors-dismissed.v1` со списком скрытых карточек. Новый провал после очистки
возвращает карточку в список.

## Формат карточки

```json
{
  "id": "linux-002",
  "section": "Linux и Bash",
  "topic": "Коды выхода",
  "difficulty": "easy",
  "question": "Какой Exit Code означает успешное выполнение команды?",
  "options": ["2", "255", "1", "0"],
  "correct_index": 3,
  "explanation": "Ноль означает успех, а ненулевой код — ошибку.",
  "source_note": "Фин Срез/Основы Linux.one",
  "tags": ["bash", "exit-code"],
  "needs_review": false
}
```

Разделы собираются из поля `section`. `needs_review` по умолчанию исключаются в обоих режимах.

## Происхождение и проверенность новых карточек

Карточки, добавленные не из заметок, несут необязательные поля метаданных:

- `provenance` — откуда карточка (`concept-audit`);
- `derived_from` — id существующих карточек, в тексте которых встречается понятие;
- `sources` — ссылки на официальную документацию, по которой сверена формулировка;
- `verified` — `true` только если источником подтверждена итоговая версия текста.

Политика: до сверки `verified: false` и `needs_review: true` (карточка не попадает в занятия),
после успешной сверки — `verified: true` и `needs_review: false`. Старой базе `verified`
массово не присваивается. Приложение сохраняет эти поля при импорте, экспорте и в резервной
копии, но в логике сессий их не использует — только `needs_review`.

## Проверка карточек

```powershell
python tools/validate.py data/cards.json
```

## Ключи хранилища

| Ключ | Содержимое |
|---|---|
| `trainer.progress.v1` | старая общая история: `{seen, correct, wrong, lastWrongAt}` |
| `trainer.training.v1` | `{attempts, correct, wrong, hinted, independent, lastAt}` |
| `trainer.reviews.v1` | `{attempts, independent, hinted, failed, lastAt}` |
| `trainer.learning.v1` | расписание: `{lastReviewedAt, dueAt, intervalDays, lastResult, independentSuccesses}` |
| `trainer.errors-dismissed.v1` | `{ "<id>": "<ISO-дата>" }` — скрытые из списка ошибок |
| `trainer.custom.v1` | карточки, добавленные через форму и импорт |
| `trainer.theme.v1` | `dark` или `light` |
| `trainer.mode.v1` | `quiz` или `recall` — способ ответа в «Учить» |

## Резервная копия

| Действие | Что сохраняет |
|---|---|
| «Экспорт карточек» | только карточки (можно сохранить обратно в `data/cards.json`) |
| «Резервная копия» | всё состояние: прогресс, тренировку, повторения, расписание, скрытые ошибки, свои карточки, тему |

Файл версии 3:

```json
{
  "schemaVersion": 4,
  "exportedAt": "2026-11-07T13:20:00.000Z",
  "theme": "dark",
  "trainer.progress.v1": { "...": "..." },
  "trainer.custom.v1": [ "...": "..." ],
  "trainer.learning.v1": { "...": "..." },
  "trainer.training.v1": { "...": "..." },
  "trainer.reviews.v1": { "...": "..." },
  "trainer.errors-dismissed.v1": { "...": "..." },
  "trainer.discussion.v1": { "...": "..." }
}
```

Совместимость: копии версий 1, 2 и 3 принимаются. Если в копии нет части слоёв, приложение
предупреждает до замены, что именно станет пустым (расписание, тренировка, повторения,
список ошибок, список «На разбор»). Порядок восстановления: проверка структуры → предложение сохранить текущую
копию → подтверждение со списком «было → станет» → замена.

Разные ключи `localStorage` пишутся отдельно, одной атомарной операции нет. Если запись
какого-то ключа не удалась, приложение честно сообщает, какие именно данные не сохранились.

## Сброс данных

- «Очистить список ошибок» — только список; статистика и расписание не меняются.
- «Сброс раздела…» — в подтверждении перечислено, что удаляется: тренировочная статистика,
  результаты повторений, старая история, расписание (карточки станут новыми) и список ошибок
  по разделу. Свои карточки, тема и способ ответа не затрагиваются.

## Чего здесь нет

Интервального повторения уровня SM-2, аккаунтов, сервера, облачной синхронизации,
мобильной сборки и ИИ-проверки свободных ответов.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| «Не удалось загрузить data/cards.json» | Открыли `file://`. Запустите `start.ps1` или `python -m http.server 8000`. |
| «Порт 8000 уже занят» | Сервер уже работает или остался процесс: `Get-NetTCPConnection -LocalPort 8000 -State Listen`, затем `Stop-Process -Id <PID>`. |
| Прогресс пропал | Другой порт или `localhost` вместо `127.0.0.1`, либо очищены данные браузера. Восстановите из копии. |
| «Резервная копия не подходит» | Файл повреждён, версия схемы неизвестна или это экспорт карточек. Данные не изменены. |
| Интервал не растёт | За один календарный день интервал увеличивается только один раз. |
| Новые не уменьшаются | Новыми считаются карточки без записи в расписании; они перестают быть новыми после первой завершённой попытки. |
